## پذیرش ماشینی

1. `npm ci`، `npm run check`، `npm test` و `npm run build` از checkout تمیز موفق شوند؛ scriptهای لازم را تعریف کن. `npm run preview` برای دیدن فایل‌های ساخته‌شده. قوانین مخصوص Pages را جداگانه در Pages preview یا محیط سازگار تست کن.
2. parser HTML خروجی همهٔ مسیرها را بررسی کند. تعداد مورد انتظار برابر `5 × (4 + N)` است که N تعداد محصولات قابل نمایش است. چهار صفحهٔ ثابت خانه، کاتالوگ، درباره و تماس‌اند. برای demo N=4. فایل‌های فنی و 404 در شمارش نیستند.
3. برای هر صفحه canonical درست، پنج alternate متقابل و x-default، lang/dir صحیح، یک H1، title محلی و لینک داخلی سالم بررسی شود. sitemap فقط canonicalهای همین مجموعه را داشته باشد. root redirect، query تماس و پاسخ واقعی 404 پس از استقرار هم تست شوند.
4. نبود دادهٔ قیمت در schema و نبود price، priceCurrency، offers، checkout یا قیمت نمونه در HTML، structured data و دادهٔ public بررسی شود. وزن بسته‌بندی، شمارهٔ محصول و اعداد در تماس قیمت محسوب نمی‌شوند.
5. با JS خاموش، صفحهٔ محصول، ناوبری موبایل، انتخاب زبان، راه تماس و متن ایمیل را امتحان کن. پارامتر نامعتبر product در تماس باید بی‌سر‌وصدا نادیده گرفته شود. در حالت production لینک mailto به ایمیل واقعی تنظیمات برسد؛ هیچ رابطی به اشتباه پیام «ارسال شد» نشان ندهد.
6. تست منفی build تولید: ترجمهٔ محصول را حذف کن یا salesEmail را به example.com برگردان؛ تست باید شکست مورد انتظار را بگیرد. fixture تست را از دادهٔ واقعی جدا نگه دار.
7. همهٔ درخواست‌های لازم برای خواندن صفحه روی دامنهٔ سایت باشند. هیچ فونت، tracker، API ترجمه یا عکس hotlink‌شده برای رندر اولیه لازم نباشد.

## پذیرش بصری و کاربردی

- عرض‌های 320، 390، 768 و 1440px. فارسی، آلمانی و چینی را در همهٔ عرض‌ها نمونه‌برداری کن. انگلیسی و اسپانیایی حداقل روی موبایل و دسکتاپ بررسی شوند. چیدمان و ترتیب فوکوس در هر دو جهت قابل دنبال‌کردن باشد.
- یک نفر بدون راهنمایی از صفحهٔ خانه نوع نگین را پیدا کند، تفاوت ظاهری آن را بخواند، زبان را عوض کند و ایمیل فروش را پیدا کند. همان مسیر را از ورودی مستقیم جزئیات نیز انجام دهد.
- کنتراست متن معمولی حداقل 4.5:1، متن بزرگ حداقل 3:1، حلقهٔ فوکوس قابل دید، skip link، کنترل‌ها با نام دسترس‌پذیر. بزرگ‌نمایی 200٪، استفاده با Tab/Enter/Escape برای کنترل‌های بازشونده، تصویر ناموجود و متن طولانی را بررسی کن.
- خوانایی عکس‌ها در کنار هم، نام‌گذاری صحیح نوع زعفران و حالت RTL جدول مشخصات با چشم بررسی شود. اصول برند و رنگ در هر پنج زبان یکسان بمانند.
- تحویل به مالک با فهرست نام تجاری، دامنه، ایمیل، عکس دارای حق استفاده، متن درباره، فهرست محصولات واقعی، نسخهٔ نوشتاری چینی و وضعیت مرور ترجمه‌ها. نتیجهٔ تست مناطق را با تاریخ ثبت کن. در گزارش پایانی، تست‌های محلی، تست‌های دامنهٔ عمومی و اقلام منتظر تأیید مالک را به تفکیک اعلام کن.
